# unity00ex1. 実機パフォーマンスチェックリスト
________________________________________
## 1. 前提知識
________________________________________
コンシューマ機はとにかくCPUが遅い

- 解凍コストやパースコストが無視できない
    - LZMA、10以上のVorbisのDecompressなど露骨に辛い
    - XML、CSV、JSONの実機利用は現実的ではない
- 数十のアセットをローディング画面でロード・パースしようとすると、10秒以上かかりがち

.

________________________________________
## 2. Audio
________________________________________
- [ ] DecompressOnLoadは、1秒未満のみで使う。推奨はVorbis
- [ ] CompressedInMemoryは、～10秒未満に対して、必ずADPCMとセットで使う
- [ ] Streamingは10秒～に対して、使う。推奨はVorbis

.

________________________________________
## 3. AssetBundle
________________________________________
- [ ] 特に理由がなければ、ChunkBasedCompression（=LZ4）
- [ ] DLフォーマットのみ、LZMAを許容する（解凍コストが重く実機では使いづらい）
- [ ] DLしても、ローカルにキャッシュ保存する際にはLZ4にする

.

________________________________________
## 4. 実機のローディング
________________________________________
- [ ] CPUブースト機能があるため、一時的にonにする

.

________________________________________
## 5. 設計
________________________________________
- [ ] XML、CSV、JSON等はEditor用。IL2CPP実機ではScriptableObjectのほうが圧倒的に早い
- [ ] Texture、Sprite、AudioClip、Prefab等は使う直前にロードが基本（オンデマンドなロード）
- [ ] 1f遅延も許されないゲームの場合のみ、事前ロードを許容する
- [ ] 事前ロードは、スプラッシュやタイトル画面でのバックグラウンドロードを活用する

.

________________________________________
## 6. ビルド設定
________________________________________
- [ ] Project Settings > Player > Other Settings > C++ Compiler Configu... > Release
- [ ] Build Profile > Development Build > Off
